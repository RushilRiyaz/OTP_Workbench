What you have now (routing.ts:42-65)

  Your current types are stubs — they have ~10 fields each. The real OTP response is much richer.

  Leg — currently a flat interface with 10 fields. Problem: the API actually returns two different leg shapes depending on mode:

  - nonTransitLeg (WALK, BIKE, CAR, etc.) — has legGeometry, steps, escooterInfo, rentedBike, and from/to can be either a station or
  fromToLocation (arbitrary coords)
  - transitLeg (BUS, TRAM, TRAIN, etc.) — has intermediateStops, headsign, tripId, routeColor, agencyName, cancelled, flexaProperties, and
  from/to are always station

  Both have legGeometry (polylines for map drawing) and alerts, neither of which exist in your current type.

  Itinerary — missing zoneInfo (tariff zones, short-distance ticket indicator). Valentin needs this for FR10.7/FR10.8.

  station — doesn't exist at all. Currently from/to are just { name, stopId?, lat, lon }. Real stations have zoneId, wheelchairBoarding, track,
   cancelled, arrival/departure times, arrivalDelay/departureDelay, alerts, etc.

  What you need to build

  Concretely, you need to add/expand these types in src/lib/routing.ts:

  1. Station — full GTFS station (name, stopId, lat, lon, zoneId, wheelchairBoarding, track, cancelled, times, delays, alerts)
  2. FromToLocation — arbitrary location (name, lat, lon, optional rental info)
  3. LegGeometry — { points: { lat, lon }[] }
  4. Alert — service alerts (header, description, category, dates)
  5. ZoneInfo — { zones, orderedZones, shortDistanceTicket }
  6. NonTransitLeg — walk/bike/car legs with transitLeg: false, from/to as Station | FromToLocation, legGeometry, steps, escooterInfo
  7. TransitLeg — transit legs with transitLeg: true, from/to as Station, intermediateStops: Station[], headsign, tripId, routeColor, etc.
  8. Leg = NonTransitLeg | TransitLeg — discriminated union (discriminant: transitLeg boolean)
  9. Expand Itinerary — add zoneInfo: ZoneInfo | null

  Why this is a blocker

  - Rushil (you): FR11.7/11.8 need legGeometry for map polylines, FR11.2 needs intermediateStops
  - Valentin: FR10.3 needs leg modes/durations for transfer scheme, FR10.7/10.8 needs zoneInfo
  - Ayman: FR12.1/12.2 needs intermediateStops + transit metadata for trip course view

  Everyone's components consume these types, so this needs to land first.

  The full API spec is at docs/api_docs/otp_routing_api.md — that's your source of truth for every field. You don't need every optional field
  (e-scooter, Flexa, car rental can be added later), but the core fields listed above are required for sprint 2 FRs
